# DroneLinkServer operations

Status: source-derived; runtime/hardware not verified for this documentation baseline. Reviewed: 2026-11-05.

1. Install a compatible Node.js/npm environment; run `npm ci` in this repository. Serial-port dependencies may require host support. Verified runtime versions remain an M1 deliverable.
2. Set the hostname-specific `config.json` entry: node ID, explicit release directory (`releaseDir`), log path, telemetry serial port, domain ID and domain API key. Missing/invalid release selection starts with warnings and disables release features; the old `firmwarePath` is ignored with migration guidance. Startup creates missing skeleton entries and exits for missing host configuration. Do not commit actual keys.
3. Start the gateway using `node index.mjs`. It provides a terminal UI and serves the legacy web interface. UDP uses port 8007; inspect `index.mjs` for web port selection. Ensure the configured serial device and local network are accessible.
4. Start the independent hosted backend at the currently hard-coded forwarding destination `http://localhost:8003` if testing ingestion. M1 will make this configurable.
5. Simulation: `npm run sim`, with suitable `sim.json` and gateway connectivity. Do not assume a simulation pass proves firmware hardware behaviour.

Root `npm test` remains a placeholder failure. Select the explicit protocol and release suites below. The old sibling-source `parseModules.js` is retired; metadata is exported by DroneNode and help is rendered during explicit Server release preparation. Firebase deployment is a separate, unverified path; do not deploy it merely because `functions/` exists.

## M1-B gateway cloud relay setup

The gateway's process configuration owns one `domain` and numeric `id` (1–254). An active-domain Owner or Platform Admin signs in to the matched hosted backend, obtains the normal CSRF token from `/api/session`, and issues `POST /api/domains/:id/gateways` with `{name,nodeAddress}` using the session, exact Origin and `X-CSRF-Token`. Copy the once-returned credential into the private hostname entry as `cloudRelay: {url: "https://your-cloud-origin", credential: "<gatewayId>.<secret>"}`. Do not commit the configuration or reuse the domain node key. The cloud URL must be an origin; loopback HTTP is accepted for local testing only. The separately scoped credential is verified before upload. Keep secrets out of diagnostics/output.

No relay configuration leaves local workbench operation available without cloud access. Domain/API key configuration alone no longer enables the old hard-coded localhost uploader. Restart the gateway explicitly after selecting the association; UI sessions do not change it. Wrong association, revocation, archive or failed upload leaves local observations available and logs only sanitized failure text. A successful upload updates unchanged suppression; a later copy retries after failure, with no autonomous/durable backlog. Restore resumes only non-revoked credentials. Owner/Admin lists safe metadata or revokes with the gateway revision through `/gateways`; file backup/command permissions remain unavailable.

Use a matched B hosted backend/persistence0.4.0 and the existing verified Client artifact. Stop older backend writers during activation; do not silently fall back to permissive pre-B ingress. Preserve existing data and recover through maintenance/roll-forward. Current local evidence is in the [owning M1-B plan](../../DroneLinkDatastore/docs/planning/m1-contracts-and-telemetry.md#slice-b-implementation-scope--2026-11-06); this runbook is not evidence of managed deployment or hardware validation.

M1-B framing closeout adds captured-query serial software regressions: a complete0xFE-prefixed mesh frame is delivered on its CRC byte, with fragmented/back-to-back frames, noise, oversized declarations and CRC corruption covered. Mesh input now uses exact declared length and normalized CRC bytes for both typed arrays and ArrayBuffers. This is software boundary evidence; the approved physical path remains ESP32 Wi-Fi/UDP, not its console USB port or binary serial telemetry.

M1-B bench teardown exposed UDP callbacks using the socket as `this`, so close/error attempted a missing `clog`. Two public socket-event regressions fail before the correction and pass with adapter-bound callbacks; the physical relay rerun exits cleanly with the socket released. The earlier successful-ingress/failed-teardown run is retained as partial evidence, not silently reported as a fully passing run.
